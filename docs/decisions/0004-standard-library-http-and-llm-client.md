# 0004. HTTP 서버와 LLM 클라이언트는 표준 라이브러리로 만든다

- 상태: 채택
- 범위: `http_server.py`, `llm/responses_api.py`

## 맥락

서비스는 인증이 필요한 POST 경로 하나와 상태 점검 경로 하나를 엽니다. 외부 모델은 리뷰 한 건에 많아야 한 번 부릅니다. 개발 중 orchestrator와의 계약이 여러 번 바뀌어서, 어댑터는 얇고 다시 쓰기 쉬워야 했습니다.

## 결정

- `http.server.ThreadingHTTPServer`로 HTTP를 처리하고, 요청은 허용 목록에 맞춰 Python으로 직접 검사합니다.
- OpenAI Responses API는 `urllib.request`로 부르고, 제한 시간을 명시하며 자동 재시도는 하지 않습니다.
- 패키지에 필수 의존성은 없습니다. `boto3`와 `duckdb`는 선택 extra `r2`에 있고, `jsonschema`는 테스트에만 필요합니다.

## 결과

- 의존성이 작고 컨테이너가 빨리 뜹니다.
- 검증, 오류 응답, 메서드 처리를 직접 써야 하고 따로 테스트해야 합니다([T-HTTP-02](../troubleshooting.md#t-http-02-리뷰-경로에-다른-메서드를-보내면-404나-html-501)).
- OpenAPI 문서가 자동으로 생기지 않으므로 `contracts/`의 JSON Schema가 기준입니다.
- 재시도는 호출하는 쪽이 정합니다. 리뷰 한 건에 비용을 두 번 내는 일을 막습니다.

## 검토한 대안

- **FastAPI 같은 ASGI 프레임워크.** 경로, 검증, 문서가 늘어나면 쓸 만합니다. 경로 하나에는 의존성만 늘고 줄어드는 코드는 적습니다.
- **공식 SDK.** 스트리밍, 사용량 보고, API 변화 대응에 도움이 됩니다. 이 서비스는 요청 모양 하나만 씁니다.
