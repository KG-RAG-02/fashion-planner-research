# 0001. 시장 수치는 코드로 계산하고 LLM은 표시된 가설에만 쓴다

- 상태: 채택
- 범위: 리뷰 조립, 타깃 고객 가설

## 맥락

리뷰에는 수치(가격 통계, 연령대 인원, 환산, 마진 시나리오)와 해석(누가 살 만한지, 어떻게 보여 주고 팔지)이 함께 들어갑니다. 수치는 같은 입력이면 언제나 같아야 하고 출처를 가리킬 수 있어야 합니다. 해석은 제한된 근거에서 만들어지는 열린 답입니다.

## 결정

- 집계, 단위 환산, 환율 적용, 반올림, 범위, 빠진 이유는 모두 SQL과 Python으로 계산합니다.
- LLM은 리뷰 한 건에 많아야 한 번, 타깃 고객 가설을 쓸 때만 부릅니다. 입력은 허용된 상품 필드, 연령대 집계, 원단 판매 목록 집계뿐입니다. 고객 행, 초안 전체, 이미지는 보내지 않습니다.
- LLM 출력은 필드마다 검사하고 가설로 표시합니다. 호출이 실패하거나 키가 없으면 치명적이지 않은 오류로 남기고, 계산한 리뷰는 그대로 돌려줍니다.

## 결과

- 수치는 모델 없이 재현하고 테스트할 수 있습니다.
- 가설은 틀리거나 일반적일 수 있으므로 관측 사실로 쓰면 안 됩니다. 가설의 `evidence_ids`는 입력으로 준 자료를 가리킬 뿐 문장마다의 증거가 아닙니다.
- 모델을 바꿔도 가설만 달라지고 수치는 그대로입니다.

## 검토한 대안

- **LLM이 수치까지 포함해 리뷰 전체를 씁니다.** 수치를 재현할 수 없고 근거 행을 추적할 수 없어 택하지 않았습니다.
- **LLM을 아예 쓰지 않습니다.** 가능한 선택입니다. 가설은 선택 기능이고 전송을 허용하지 않으면 꺼져 있으므로, 생성 문장이 필요 없는 배포는 꺼 두면 됩니다.
- **JSON 모드와 수동 검사 대신 엄격한 JSON Schema 출력을 씁니다.** 같은 모델로 비교해 볼 가치가 있으나 아직 측정하지 않았습니다.
