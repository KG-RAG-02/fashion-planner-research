# 0003. 저장소의 객체 집계에는 DuckDB와 httpfs를 쓴다

- 상태: 채택
- 범위: 스냅샷 빌더, 원본 객체 개발 모드

## 맥락

집계는 S3 호환 버킷에 있는 고객 CSV와 상품·거래 Parquet을 조인하고, 카테고리를 매핑하고, 연령대별 고유 고객 수와 가격 분위수를 계산합니다. 자료는 과거 자료이고 읽기 전용입니다.

## 결정

- DuckDB의 `httpfs` 확장으로 버킷에서 필요한 열만 직접 읽고, 조인과 집계는 SQL로 씁니다.
- `duckdb>=2,<3`을 요구합니다. 이미지는 빌드 때 `httpfs`를 설치하고, 요청 처리 중에는 확장을 설치하지 않습니다.
- 연결마다 스레드 수, 메모리 한도, 절대 경로 임시 디렉터리를 직접 정합니다.
- 연령 쿼리와 가격 쿼리를 다른 연결에서 실행해, 앞 쿼리의 해시 상태를 놓은 뒤에 다음 쿼리를 시작합니다.

## 결과

- 데이터베이스 서버가 필요 없고, 노트북과 이미지에서 같은 엔진을 씁니다.
- Parquet은 필요한 열만 읽어 읽기량이 작습니다. 고객 CSV는 여전히 전부 읽습니다.
- DuckDB의 저장 형식과 확장 빌드는 주 버전에 묶이므로 버전 고정이 중요합니다([T-DEP-01](../troubleshooting.md#t-dep-01-duckdb-1x가-duckdb-20-파일을-열지-못함)).
- 메모리 사용은 설정에 달려 있고, 호스트 기준 기본값은 컨테이너에서 안전하지 않습니다([T-DATA-01](../troubleshooting.md#t-data-01-컨테이너에서-연령-집계가-메모리-부족으로-실패)).

## 검토한 대안

- **pandas.** 작은 발췌에는 충분하지만, 거래 표 전체를 Python 객체로 올리면 메모리가 훨씬 많이 듭니다.
- **PostgreSQL.** 여러 사람이 쓰는 살아 있는 저장소에 맞습니다. 여기서는 바뀌지 않는 데이터를 위해 서버와 적재 단계가 추가됩니다.
- **호스팅 웨어하우스.** 규모가 크거나 분석가가 많으면 합리적이지만, 정해진 집계 몇 개에는 필요하지 않습니다.
